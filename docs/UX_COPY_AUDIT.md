### 动词短语规范
- 按钮 = 动词 + 宾语，≤3 词：「刷新二维码」「清理缓存」；继续动作不加句号。
- 进行中用「…」：正在获取二维码…、正在加载 MV…。
- 空态句式：**先一句现状（「暂无 X」/「还没有 X」），再一句出路**。例：「暂无推荐歌单」「登录后可查看每日推荐」。
- 错误句式模板：`{对象}{失败/超时/暂不可用}，{出路}`——出路必须是用户可执行的动作（重试 / 稍后再试 / 换一首歌 / 登录后查看），禁止死胡同。

### 错误三段式（rules/03）
发生了什么 → （已知且安全时）原因 → 下一步。错误码（如 20028）降级为「（代码 20028）」括注，不作标题；异常对象 `$e` 一律不进用户文案。

## 二、主要发现与修复（按严重度）

**High**
- 异常泄漏进 UI：`下载失败：$e`、`FM 启动失败：$e`、`收藏失败：$e`、`MV 加载失败：$e`、`不支持的 MV 链接协议：$url`、登录失败拼接后端 error → 全部改为「…失败，请重试」句式（内部细节保留在 debugPrint / 日志层）。
- 内部术语泄漏：「（接口待实测）」「（needs probe）」「端点待实测」「待后端就绪」「缓存能力未装配」「数据能力未装配」「下载能力未装配」「MV 门面不可用」→ 统一「暂未开放 / 暂不可用」。
- 死胡同错误：「数据解析失败」「服务暂时不可用」无下一步 → 补「请重试 / 请稍后重试」。

**Medium**
- 术语不一：音质档位/音质/档位 → 音质；播放倍速/播放速度/倍速 → 倍速；音乐库/曲库 → 曲库。
- 「登录失败，请检查账号信息后重试」替代裸后端错误透传（同时不确认账号存在性）。
- 空态误导：「暂无每日推荐（登录后可能可见）」→「登录后可查看每日推荐」。

**Low**
- 标点统一：arb 中错误/风险句原用空格分句（「网络异常 请重试」）→ 统一逗号/句号。
- 大小写/句式：英文 error 值统一「句首大写 + 句号 + 请重试出路」结构。
